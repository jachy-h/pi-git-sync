## 已完成：Phase 0

### 已完成

- 建立 v0.3 进度文件，后续每个阶段在此追踪。
- 将命令注册契约改为目标 API：补全只包含 `status`、`diff`。
- 增加无参数命令不再打开菜单、取消 setup 无副作用的失败测试。
- 增加 `init`、`pull`、`push`、`push --continue` 及未知参数的无副作用拒绝测试。
- 增加统一领域入口 `run()` 的失败测试契约。
- 记录 Phase 0 红灯基线：17 failed / 34 tests。

## 已完成：Phase 1

### 已完成

- `src/operation-result.ts` 增加 `RunOptions`、`RunResult`、`RunMode`、`SyncPhase`。
- `PiSyncCommands.inspectLifecycleState()` 增加 uninitialized / initialized / broken 三态探测。
- `PiSyncCommands.run()` 实现 setup、pending recovery、pull → push 串行编排。
- pull 失败或审批等待时停止，不进入 push；pull noop 仍进入 push。
- push 阶段保留 ahead commit 同步；聚合两阶段结果和单次 reload 标志。
- 统一编排持有顶层 sync 锁，内部阶段避免嵌套锁。
- 旧 `push-rebase-conflict` 和 `apply-failed` pending state 接入普通 `run()` 恢复路径。

### 已完成

- package approval 重入路径已覆盖：审批后重新调用 `run()`，不复用旧 preparation。

## 已完成：Phase 2

### 已完成

- `index.ts` 无参数路由统一到 `handlePiSync`。

- 补全和 description 只暴露 `status`、`diff`。
- 未知参数和旧写命令 fail closed，并返回 v0.3 迁移提示。
- UI 负责 URL 输入、Package 审批、通知和一次性 reload；领域层负责状态与执行顺序。

### 已完成

- 入口与统一编排回归测试全部通过。
