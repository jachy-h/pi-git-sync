# v0.2 实施进度

> 更新时间：2026-07-26
> 当前状态：实现中，尚未达到发布条件。

## 已完成

### CORE-04：Git 严格错误模型

- 新增 `GitCommandError`，包含 args、cwd、exitCode、stdout、stderr、timedOut。
- `gitExec()` 在 Git 非零退出时抛错。
- 新增 `gitProbe()`，用于预期失败的探测命令。
- 更新 status、fetch、pull、push、rebase、commit、init 等调用点。
- Git 失败测试已更新并通过。

### CORE-01：同步基线收敛

- state schema 从 v2 升级到 v3。
- `pendingOperation` 改为结构化对象。
- `MaterializePlan` 新增 `nextBaseline` 和 `hasStateChanges`。
- `planMaterialize()` 构建完整最终 baseline。
- `applyCurrent()` 在无文件 I/O 时也能收敛 state。
- 成功 apply 使用完整 `nextBaseline` 替换旧 baseline，删除项不会残留。
- apply 后更新 `lastSyncedCommit` 和 `lastSyncedAt`。
- 现有状态、materialize、backup、push、UI 测试已适配 schema v3。

### CORE-02：结构化 Push

- 新增 `src/operation-result.ts`。
- 新增 `PushPreparation`、`preparePush()`、`executePush()`。
- preparation 阶段完成 capture、validation、secret scan、diff 和 fingerprint。
- execute 阶段重新校验 HEAD/worktree fingerprint，避免确认期间静默使用旧 diff。
- `push()` 复用同一 preparation/execute 流程，保留原有可编程入口。
- Extension UI 不再通过 `message.includes(...)` 控制 push 流程。
- capture 后 push、取消后重试、repo 已 dirty、两设备 E2E 已验证。

### SEC-01：路径与符号链接边界

- 新增 `src/path-safety.ts`。
- 新增 `resolveRepoSyncRoot()`、`resolveWithinRoot()`、`assertNoSymlinkComponents()`。
- 接入 inventory、capture、materialize、backup、validate、packages 和 secret scan。
- inventory/backup 对 symlink 改为阻断，而不是静默跳过。
- 保留 macOS `/var` 系统路径兼容，不把系统前缀误判为用户仓库 symlink。

## CORE-03：单一分支语义

- `config.branch` 增加空白、控制字符等基础校验，并在 Git 层使用
  `check-ref-format --branch` 做严格校验。
- pull、push、capture、apply、init、rebase、status、diff 统一使用
  `config.branch`，不再从当前分支推断同步目标。
- 干净工作树可自动切换到配置分支；dirty、rebase 或 merge 状态下明确阻断，
  不自动切换用户工作树。
- init 的 scaffold、远端检查和 state 更新均遵循配置分支。
- 新增非 `main` 分支同步、dirty 分支切换保护和 state branch 回归测试。

## SEC-02：Package 信任与回滚已完成

已完成：

- package source 严格解析，支持字符串和 `{ source }` 对象统一校验。
- 拒绝 `file:`、绝对路径、相对路径和控制字符 source。
- 新增 package trust store：`.pi-sync/package-trust.json`。
- 新增 `PackagePlan`、`planPackageChanges()`、`approvePackagePlan()`。
- 新增 `approvalRequired`，无审批时不会执行 `pi install`。
- package source 继续通过 `execFile` argv 执行，未使用 shell。
- 新增 `test/package-trust.test.ts`，覆盖未审批阻断、对象 source、remember trust、
  本地路径拒绝，以及安装时序和失败恢复。
- 当前运行中的 `npm:@jachy/pi-git-sync` 被视为已安装的内置可信扩展，
  不触发重复安装审批。
- package 流程已拆为 `preparePackagePlan()` → `approvePackagePlan()` →
  materialize settings → `executePackagePlan()` → save state；审批不再触发安装，
  安装失败会恢复 agent 文件并记录 `apply-failed` pending operation。
- `apply`、`pull`、`init` 已返回结构化 `CommandResult`（保留 init 的兼容字段），
  package 未审批时返回 `approval_required` 和 package 明细。
- TUI/RPC 共用明确的 package approval 确认入口；pull 在 fast-forward 后等待审批时，
  重试会直接 apply，不会丢失已拉取的变更。
- Extension package approval 取消与确认流程已覆盖测试。
- `createBackup()` 改为 fail-closed：所有计划文件先完成快照，备份数据和 manifest
  写入后进行 hash 校验；任意读取、写入或校验失败都会清理残留备份并抛错。
- apply 在备份失败时返回结构化失败结果，阻止后续 materialize 写入；新增备份失败
  阻断和无残留测试。

已完成回滚补强：

- package 安装失败后按逆序移除本次新增/变更 package，并尝试重新安装变更前的旧 source。
- 回滚失败会写入 `rollbackErrors` 并进入结构化错误结果，不伪装成同步成功。
- 新增多 package 部分失败、旧版本恢复失败回归测试；`packages-reconcile` 共 7 tests 通过。

说明：package manager 本身仍只提供 best-effort 回滚能力；无法恢复时会明确暴露失败，
不会声称已完成恢复。

## CORE-05：Bootstrap 已完成

- bootstrap 不再把配置仓库当作 Pi package 安装。
- 改为安装固定版本的 `npm:@jachy/pi-git-sync@<version>`；可通过
  `PI_GIT_SYNC_VERSION` 为镜像或测试环境显式指定版本。
- clone、目标分支选择和 state 初始化统一交给 `/pisync init <repo-url>`，脚本不再
  硬编码 `main`，也不会忽略 Git 失败。
- 安装失败返回非零且不显示成功；成功和失败路径均有 bootstrap 集成测试覆盖。

## DEP-01：依赖 advisory 已清理

- Pi peer 依赖和测试解析版本更新到 `0.82.1`，Node engine 与该 Pi 版本要求对齐到
  `>=22.19.0`。
- 通过 `test-exclude@8` 和 lockfile 固定 `brace-expansion` 到 `5.0.8`，清理
  `brace-expansion@5.0.7` 的 high advisory，同时保持 Vitest coverage 正常工作。
- `npm audit --omit=dev --audit-level=high` 和
  `npm audit --audit-level=high` 均通过；CI 继续执行这两道门禁。

## State v2 → v3 安全迁移已完成

- 迁移前先原子备份旧 state，迁移完成后持久化 v3，避免重复猜测 baseline。
- local/repo hash 相同的路径自动收敛；两边都不存在的旧条目移除。
- local/repo 不一致、路径不可用或存在 symlink 时保留旧 baseline，并写入
  `migrationReport.conflicts`，不自动选边。
- 新增 equal、mismatch、both-deleted 和迁移持久化回归测试。

## 尚未开始或待完成

- 确认 `0.2.0` 版本号、变更日志与正式发布流程；当前源码包版本仍为 `0.1.16`。
