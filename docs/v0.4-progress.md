## 已完成：Phase 0 — 失败测试与结果契约

- 增加 `SyncConflictRequest`、冲突选择和 local/remote 矩阵测试。
- 将手动 merge 测试改为断言结构化冲突详情，不依赖固定 message 前缀。
- 固定 Abort 与 v0.3 手动处理行为兼容。

## 已完成：Phase 1 — 结构化冲突结果

- `src/operation-result.ts` 增加冲突类型、路径和 `RunResult.details` 结构。
- capture、rebase、apply 冲突路径统一生成结构化 conflict request。
- `syncInternal()` 在冲突后停止 push，并将冲突提升到顶层结果。
- UI 分派不再通过 message 文案识别手动 merge。

## 已完成：Phase 2 — 四选一 UI 与 agent handoff

- 冲突 UI 提供四个明确选项：
  - Ask agent
  - Abort / manual merge
  - Use local / current device
  - Use remote / shared branch
- 无 UI、Escape 和取消选择均安全回退到 Abort/manual merge。
- Ask agent 使用 `pi.sendUserMessage()`，不自动选边、不自动循环同步。
- 自动选边前提供 destructive confirm，并按结果聚合 reload 行为。

## 已完成：Phase 3 — 自动 local/remote resolution

- 新增 `src/conflict-resolution.ts`，集中处理 Git 冲突事务。
- 支持 unmerged stage 枚举、ref/stale 检查和 modify/delete 冲突映射。
- Use local / Use remote 只影响冲突路径，非冲突变更继续正常合并。
- 自动解决流程接入重新 fetch、加锁、工作树检查、validation、secret scan、merge commit 和普通 push。
- 保留 device branch，不使用 force push。
- 接入 backup、apply、package approval 和失败恢复路径。
- 覆盖并发推进、dirty worktree、push non-fast-forward、validation/secret scan/apply 失败等恢复场景。
- 增加双设备 E2E，验证冲突保留和最终收敛。

## 已完成：Phase 4 — 定向架构清理

- 删除重复的 `src/minimatch.ts`，统一使用 `src/glob.ts`。
- 删除仅供旧测试参考的 `src/settings.ts`，测试 helper 移至 `test/helpers/settings-legacy.ts`。
- 冲突 Git primitive 集中在 `src/conflict-resolution.ts`，避免继续堆积到 `commands.ts`。
- 未进行与 v0.4 无关的大规模同步流程重构。
